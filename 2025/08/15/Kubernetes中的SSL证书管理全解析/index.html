# Kubernetes 中的 SSL 证书管理全解析：cert-manager 原理与组件

在 Kubernetes 集群中，如果要为服务提供 HTTPS 访问，最常见的做法是通过 Ingress Controller 配合 cert-manager 自动申请和管理 TLS 证书。

本文将用通俗易懂的方式，介绍 cert-manager 申请证书时涉及的组件、它们的作用，以及整个签发原理。

# 1. cert-manager 中的核心组件

在 cert-manager 的世界里，有几个非常重要的 CRD（自定义资源类型），它们负责证书申请与生命周期管理。

# 1.1 Issuer / ClusterIssuer

  • 作用：定义证书签发的 “颁发机构” 配置。

  • 区别：

    • Issuer：作用域是命名空间级，只能为所在 namespace 中的证书提供签发服务。
    • ClusterIssuer：作用域是集群级，任何 namespace 都能用。

  • 内容：

    • 签发类型（如 ACME / CA / SelfSigned）
    • ACME 服务器地址（如 Let’s Encrypt）
    • 验证方式（HTTP-01 / DNS-01）
    • 账号邮箱等信息

# 1.2 Certificate

  • 作用：声明需要申请的证书信息。

  • 内容：

    • 使用哪个 Issuer / ClusterIssuer
    • 绑定的域名（dnsNames）
    • 存储证书的 Secret 名称
    • 证书的有效期要求

  • 状态字段：会记录 Ready 状态、有效期、上次续期原因等。

示例：

apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: my-tls
  namespace: default
spec:
  secretName: my-tls-secret
  dnsNames:
    - example.com
  issuerRef:
    name: letsencrypt-http01
    kind: ClusterIssuer

# 1.3 Order

  • 作用：cert-manager 与 ACME 服务器（例如 Let’s Encrypt）交互时的临时对象，用于记录一次签发或续签过程。

  • 包含信息：

    • 当前证书签发进度
    • 对应的 Challenge 记录

  • 生命周期：证书申请完成后，Order 会自动被清理。

# 1.4 Challenge

  • 作用：ACME 协议中，CA（证书颁发机构）用来验证你对某个域名的所有权。

  • 类型：

    • HTTP-01：在域名下 .well-known/acme-challenge/ 放置验证文件。
    • DNS-01：在域名的 DNS TXT 记录中写入指定 token。

  • HTTP-01 特点：

    • cert-manager 会创建一个 solver pod 和对应的临时 ingress，把验证路径路由到这个 pod。
    • 验证成功后，solver 会被删除。

# 1.5 Solver（HTTP-01 Solver）

  • 作用：在 HTTP-01 验证中，负责对外暴露验证文件的服务组件。

  • 实现方式：

    • cert-manager 会为每个域名的 Challenge 创建一个临时 Ingress，并将 /.well-known/acme-challenge/ 路径流量转发到 solver pod。
    • 验证完成后，相关 ingress 与 pod 会自动清理。

# 2. 证书签发的工作原理

下面是 HTTP-01 验证的基本流程：

  1. 创建 Certificate

    • 用户提交一个 Certificate 对象，指定需要的域名、Issuer 等。

  2. 生成 Order

    • cert-manager 根据 Certificate 创建一个 Order 对象，向 ACME 服务器发起签发请求。

  3. 生成 Challenge

    • ACME 返回 Challenge 请求（HTTP-01/DNS-01）。

  4. 部署 Solver

    • 对于 HTTP-01，cert-manager 创建一个临时 ingress + pod 来响应 ACME 的验证请求。

  5. ACME 验证

    • CA 访问 http://<your-domain>/.well-known/acme-challenge/<token>，验证域名所有权。

  6. 签发证书

    • 验证通过后，ACME 颁发证书，cert-manager 将其保存到指定的 Secret。

  7. 更新 Certificate 状态

    • 证书 Ready，Ingress Controller 使用新证书提供 HTTPS。

  8. 自动续期

    • cert-manager 会在证书到期前（默认 2/3 生命周期时）自动续期。

# 4. 常见问题与建议

  • HTTP 强制跳转 HTTPS：

    在 HTTP-01 验证期间必须允许 HTTP 直通，否则验证会失败。

  • 多 ingressClass 环境：

    确保 solver ingress 的 ingressClassName 与实际处理的 Ingress Controller 匹配。

  • DNS-01 更稳妥：

    如果 HTTP-01 验证受限（多层代理、CDN、80 端口被占用），建议改用 DNS-01。

  • 监控证书状态：

kubectl get certificate -A

# 总结

cert-manager 让 Kubernetes 上的证书管理自动化变得非常简单，但理解它背后的组件与流程，能帮助我们快速定位问题、选择合适的验证方式，并在证书续签失败时高效排障。
